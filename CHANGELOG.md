# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии соответствуют сборкам, публикуемым в папку релиза.

## [0.9.0] — 2026-10-02

### Добавлено

- Настройка «Серии, для которых не удаляем окончания» на вкладке
  «Настройки анализа» (блок «Дополнительные параметры обработки»).
  Серии перечисляются через запятую, поле подстраивает высоту под содержимое.
  Если значение на момент правила 8 начинается с серии из списка:
  - окончания не удаляются: `H74H-16P DN50` сохраняется целиком;
  - технические блоки (`DN50`, `PN16`, `M6` …) не мешают форме «* *» —
    при `-` в «Доп. символах» такие коды попадают в файл для 1С;
  - классификатор правила 12 не применяется (безусловное удаление
    и связь с другим изделием действуют как обычно).

  Сравнение без учёта регистра и с приведением похожих букв по карте замен:
  `H74H` совпадает и с `Н74Н` на кириллице.
- Правило 12: связь с другим изделием через существительное в родительном
  падеже — `Крышка насоса AB12`, `Ремкомплект распределителя AB12`,
  `Комплект уплотнений клапана AB12`. Код в таком случае удаляется, как при
  связи через предлог. Прилагательные и отглагольные существительные
  на `-ния`/`-тия` пропускаются; просмотр прекращается на коде, числе,
  союзе, аббревиатуре или после запятой.
- После слов-наборов (`комплект`, `набор`, `упаковка`, `пачка`, `партия`)
  следующее слово считается содержимым набора: `Комплект прокладок AB12`
  не удаляется.
- Файл `Исключения родительного падежа.txt` — слова в родительном падеже,
  не означающие другое изделие (`давления`, `очистки`, `воздуха` …).
  Создаётся при первом запуске, значения читаются с четвёртой строки;
  если файла нет — используется встроенный список.
- В список слов удаления кода по умолчанию добавлены `корпус` и `провод`.
  В уже существующий файл `Слова удаления кода.txt` их нужно добавить вручную.
- Самопроверка разделена на три набора: правила 1–11 (правило 12 выключено),
  правило 12, серии без удаления окончаний (с проверкой готовности для 1С).
  Добавлены кейсы на резьбу (`T`), родительный падеж (`G`), правило 12 (`R`)
  и серии (`K`); сбой одного кейса не прерывает прогон.

### Изменено

- Строки с дубликатами комм. кода у разных артикулов больше не включаются
  в `Коды для загрузки в 1С.xlsx` — они выводятся только
  в `Дубликаты в кодах для переноса в 1С.xlsx`.
- Файл `Дубликаты в кодах для переноса в 1С.xlsx` создаётся, только если
  найден хотя бы один дубликат; выделение красным в нём не используется.
- Удалено выделение дубликатов красным в `Коды для загрузки в 1С.xlsx`.
  В `Коды для ручной проверки.xlsx` артикулы дубликатов по-прежнему
  выделяются красным полужирным шрифтом.
- Новый текст предупреждения на вкладке групповой обработки:
  «ВНИМАНИЕ!!! При формировании файла Коды для загрузки в 1С.xlsx обнаружены
  дубликаты комм. кодов для разных артикулов, проверьте их в файле
  "Дубликаты в кодах для переноса в 1С.xlsx"!». Тот же текст выводится
  в `Применённые правила.txt`.
- В сводке дубликаты показываются как «исключены из 1С»; сумма строк трёх
  основных файлов меньше общего числа строк на количество дубликатов.
- Правило 5 распознаёт резьбу не только в начале токена, но и после
  разделителей `-`, `/`, `(`, `[`, `,`, `;`, `=`: `6525 8-М5-М` → `6525 8-M5-M`,
  `-М0,75х0,25-F` → `-M0,75X0,25-F`. Диаметр с нуля допускается только
  в виде `М0,` / `М0.`.
- Правило 10 заменяет кириллическую `М` по общей карте замен, как остальные
  буквы (`МАХ-12Т` → `MAX-12T`, `М004-25` → `M004-25`), а не только
  в обозначениях резьбы.
- Ожидаемый результат кейса S4: `40Х` → `40X` — допустимое ложное
  срабатывание, короткую форму не отличить от марки стали.

### Исправлено

- Защита обозначений `М004`, `М008` от замены как резьбы, заявленная
  в 0.6.2–0.6.3, не работала: ограничение было только в правиле 10,
  а правило 5 выполнялось раньше и заменяло `М`. Теперь ограничение
  в самом правиле 5: `КЭМ-М004-РФ01` не меняется.
- Безусловное удаление по словам, заявленное в 0.6.1 как независимое,
  по-прежнему срабатывало только для значащих слов: `конденсатор`,
  `саморез`, `шуруп`, `хомут` не удалялись. Теперь проверяется первое слово
  значения до удаления значащих слов, независимо от их списка (только при
  включённом правиле 12). Если файла нет, используется встроенный список.
- Удалённый правилом 12 код сохранял исправленное значение, из-за чего
  давал ложные дубликаты. Теперь результат очищается, исходный код
  подсвечивается целиком, такие строки не участвуют в поиске дубликатов.
- Ошибки компиляции CS0136 в `ApplyHomoglyphs` (повторное объявление
  `i` и `repl`).

## [0.6.3]

### Добавлено

- Файл `Слова удаления кода.txt`: если значение начинается с такого слова,
  код удаляется целиком, минуя классификатор правила 12. Файл создаётся
  автоматически при первом запуске, значения читаются с четвёртой строки.
- Отдельный признак результата `CatalogReviewForcedEmpty` для безусловного
  удаления — отличает его от пустого результата по другим причинам.
- Строка выбора файла «Слова удаления кода» в разделе настроек.

### Исправлено

- Замена кириллических гомоглифов больше не затрагивает марки стали внутри
  составных кодов вида `F21-50-PN25-10Х17Н13М2Т-TYPE-E`. Раньше марка
  распознавалась только в целом токене, поэтому в длинных кодах без
  пробелов кириллица в ней заменялась на латиницу.
- Правило «Замена символов в резьбе» не трогает артикулы вида `М004`,
  `М008`: для обозначений `М0…` замена выполняется только при наличии
  десятичной дроби (`М0,5`). *Фактически исправлено в 0.9.0.*
- Правило «Замена символов в резьбе» срабатывает, когда слева от `М`
  стоит дефис или минус (`переходник-М0,5`).

## [0.6.2]

### Исправлено

- Обозначения резьбы вида `М12`, `М10x1.5` обрабатываются по основной
  логике, ограничение по десятичной дроби применяется только к `М0…`.
- Составные коды `КЭМ-М004-РФ01` не преобразуются: `М` в середине
  дефисного блока не считается резьбой. *Фактически исправлено в 0.9.0.*

## [0.6.1]

### Добавлено

- Правило 12: безусловное удаление кода для слов из внешнего списка.

### Исправлено

- Безусловное удаление срабатывало не для всех значений: проверка была
  связана с признаком «начиналось со значащего слова», который не всегда
  выставлялся. Теперь проверка независима. *Фактически исправлено в 0.9.0.*

## [0.6.0]

### Добавлено

- Правило 12 «Проверка кода после значащего слова»: классификация остатка
  после удаления значащих слов.
- Файл `правила обработки значений коммерческого кода.txt` с текстом
  справки.
- Настройки размеров шрифтов интерфейса.
- Профиль публикации в папку.

### Изменено

- Порядок применения правил отличается от порядка в техническом задании:
  правило 9 выполняется первым, так как при совпадении обработка
  прекращается.
