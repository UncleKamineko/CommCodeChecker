# CommCodeChecker

Настольное приложение для нормализации коммерческих кодов номенклатуры
перед загрузкой в 1С. Обрабатывает значения по набору правил, разделяет
результат на «коды для загрузки в 1С», «коды для ручной проверки»,
неизменённые коды и дубликаты, формирует отчёт.

Windows Forms, .NET 8.

## Возможности

- **Одиночная проверка** — ввод артикула и коммерческого кода, разбор
  с подсветкой сработавших правил.
- **Групповая обработка** — загрузка Excel-файла, обработка всех строк,
  распределение результата по файлам.
- **Проверка ИМ** — отдельный набор правил для кодов и артикулов интернет-магазина.
- **Настраиваемый набор правил** — каждое правило включается и выключается
  независимо; правила «Удаление значащих слов» и «Удаление окончания»
  переключаются только совместно.
- **Внешние файлы конфигурации** — списки слов, окончаний, исключений
  и карта замен символов правятся без пересборки.
- **Контроль дубликатов** — одинаковый комм. код у разных артикулов
  не попадает в файл для 1С и выносится в отдельный файл.
- **Отчёт** — сводка по правилам, категориям строк, сбоям и дубликатам.

## Сборка и запуск

```bash
git clone https://github.com/UncleKamineko/CommCodeChecker.git
cd CommCodeChecker

dotnet build src/CommCodeChecker/CommCodeChecker.csproj -c Release
dotnet run --project src/CommCodeChecker/CommCodeChecker.csproj
```

Публикация в папку:

```bash
dotnet publish src/CommCodeChecker/CommCodeChecker.csproj -c Release -o ./publish
```

Профиль публикации — `src/CommCodeChecker/Properties/PublishProfiles/FolderProfile.pubxml`.
Перед использованием поменяйте в нём `PublishDir` на свой путь.
Файл `FolderProfile.pubxml.user` содержит локальные пути машины разработчика.

Программа рассчитана на запуск из папки с правом записи (не из `Program Files`):
файлы конфигурации и результаты создаются рядом с исполняемым файлом.

## Файлы конфигурации

Папка `Файлы конфигурации` создаётся при запуске рядом с исполняемым файлом.
Отсутствующие файлы создаются из шаблонов; существующие не перезаписываются —
новые значения шаблонов в уже созданные файлы нужно добавлять вручную.

| Файл | Формат | Назначение |
|---|---|---|
| `Значащие слова.txt` | текст | слова, удаляемые из значения (правило 7) |
| `Удаляемые_окончания.txt` | текст | окончания в конце значения (правило 8), `*` — один любой символ |
| `Артикулы_исключения.xlsx` | XLSX, 3 листа | артикулы, для которых код не нужен (правило 9) |
| `Слова удаления кода.txt` | текст | слова, при которых код удаляется целиком (правило 12) |
| `Исключения родительного падежа.txt` | текст | слова в род. п., не означающие другое изделие (правило 12) |
| `Замены символов.xlsx` | XLSX | карта замен кириллицы на латиницу (правило 10) |
| `Правила проверки комм. кода для ИМ.xlsx` | XLSX | правила для кодов ИМ |
| `Правила проверки артикула для ИМ.xlsx` | XLSX | правила для артикулов ИМ |
| `правила обработки значений коммерческого кода.txt` | текст | текст правил на вкладке «Настройки анализа» |

Путь к любому файлу, кроме `Исключения родительного падежа.txt`, можно
переопределить в настройках; без этого используется файл из папки по умолчанию.

### Текстовые файлы

Шаблон: строка описания, строка правил добавления, пустая строка, затем
значения — по одному в строке. Кодировка определяется автоматически
(BOM → UTF-8 → Windows-1251).

```
Слова, при наличии которых в начале коммерческого кода он полностью удаляется
Правила добавления слов: по одному значению в строке, без пробелов в начале и в конце

корпус
конденсатор
```

- `Слова удаления кода.txt` и `Исключения родительного падежа.txt` читаются
  **с четвёртой строки**.
- `Значащие слова.txt` и `Удаляемые_окончания.txt` читаются целиком;
  служебные строки отсекаются по началу (`Удаляемые слова`, `Удаляемые окончания`,
  `Правила добавления`, `ВНИМАНИЕ`, `#`, `//`).

Список слов удаления по умолчанию: корпус, конденсатор, провод, болт, винт,
шайба, гайка, саморез, шуруп, хомут. Сравнение — по точному совпадению слова
без учёта регистра, без словоформ.

### Файл исключений артикулов

| Лист | Условие |
|---|---|
| `Начинается с` | артикул начинается с указанного текста |
| `Заканчивается на` | артикул заканчивается на указанный текст |
| `Содержит` | артикул содержит указанный текст |

`*` — ровно один любой символ. Первая строка листа — заголовок.

## Настройки анализа

Вкладка «Настройки анализа», блок «Дополнительные параметры обработки»:

| Параметр | Действие |
|---|---|
| Учитывать падежи и число значащих слов | точное совпадение / парадигмы / по корням |
| Доп. символы, допустимые в файле для 1С | символы сверх `0-9` и `A-Z`, например `-` |
| Неизменяемые сочетания кириллицы | через запятую; правило 10 их не заменяет (`ТВСР,НН`) |
| Серии, для которых не удаляем окончания | через запятую; см. [Серии номенклатуры](#серии-номенклатуры) |

Правило 6 приводит все виды тире к знаку минус (`-`, U+002D). Чтобы коды
с минусом попадали в файл для 1С, добавьте `-` в «Доп. символы».

## Правила обработки

Правила применяются в порядке `RuleCatalog.ApplyOrder`; в интерфейсе и отчёте
они показываются в порядке ТЗ (`RuleCatalog.DisplayOrder`).

| Порядок | № по ТЗ | Правило | Что делает |
|---|---|---|---|
| 1 | 9 | Комм. код удалён по виду артикула | совпадение с «Артикулы_исключения.xlsx» — код пустой, обработка прекращается |
| 2 | 3 | Удаление служебных символов | невидимые и управляющие символы; неразрывные пробелы → пробел |
| 3 | 6 | Замена тире на минус | все виды тире → `-` |
| 4 | 2 | Удаление лишних пробелов | схлопывание и обрезка по краям |
| 5 | 5 | Замена символов в резьбе | `М12х1.5` → `M12X1.5` (точку меняет правило 1) |
| 6 | 4 | Замена «х» в размерах | `20х20х3` → `20x20x3`, только целый токен |
| 7 | 1 | Замена точки на запятую | десятичные числа в резьбе, размерах, с единицами измерения |
| 8 | 7 | Удаление значащих слов | слова из «Значащие слова.txt» и «осиротевшие» предлоги |
| 9 | 8 | Удаление окончания | окончания из «Удаляемые_окончания.txt», кроме серий из настроек |
| 10 | 10 | Замена кириллицы на латиницу | по карте замен, с защитой марок стали |
| 11 | 2 | Удаление лишних пробелов | повторно, после удаления слов |
| 12 | 11 | Оставить код, совпадающий с артикулом | если артикул есть в значении — остаётся только он |
| 13 | 12 | Проверка кода после значащего слова | безусловное удаление и классификация остатка |

### Правило 5: обозначение резьбы

- `М` распознаётся в начале строки или после разделителя (пробел, `-`, `/`,
  `(`, `[`, `,`, `;`, `=`): обрабатываются `6525 8-М5-М` и `-М0,75х0,25-F`.
- Диаметр с нуля допустим только как `М0,` или `М0.` (`М0,5`):
  резьбы `М00…` не бывает, поэтому `-М004-` в `КЭМ-М004-РФ01` резьбой не считается.
- Правило 10 заменяет кириллическую `М` по общей карте замен, как остальные буквы:
  `М004-25` → `M004-25`.

### Правило 7: удаление значащих слов

Удаляет слова из «Значащие слова.txt» (с учётом словоформ по настройке),
затем — оставшиеся без значащих соседей служебные слова (`с`, `для`, `and`, `with` …).
Если удалено слово, стоявшее в начале значения, строка помечается синей заливкой
в файле ручной проверки.

### Правило 8: удаление окончания

Окончание удаляется, только если оно было окончанием значения и до удаления
значащих слов (защита от потери значимых чисел).

#### Серии номенклатуры

Если значение на момент правила 8 начинается с серии из настройки
«Серии, для которых не удаляем окончания»:

- окончания не удаляются: `H74H-16P DN50` сохраняется целиком;
- технические блоки (`DN50`, `PN16`, `M6`, `A2-70` …) не мешают форме «* *»;
- классификатор правила 12 не применяется.

Сравнение без учёта регистра и с приведением похожих букв по карте замен:
серия `H74H` совпадёт и с `Н74Н` на кириллице.

### Правило 10: замена кириллицы на латиницу

- Работает по карте `Замены символов.xlsx`. Если в значении есть кириллица
  вне карты, значение не меняется целиком (`ПЗК-RU52`, `КЭМ-М004-РФ01`).
- Марки стали на кириллице (`08Х18Н10`, `12Х18Н10Т`, `40ХН2МА`) защищены,
  в том числе внутри составных кодов (`F21-50-PN25-10Х17Н13М2Т-TYPE-E`).
  Строка с такой маркой всегда идёт на ручную проверку.
- Короткие формы вроде `40Х` маркой не считаются и заменяются (`40X`) —
  допустимое ложное срабатывание.
- Сочетания из настройки «Неизменяемые сочетания кириллицы» не заменяются.

### Правило 12: проверка кода после значащего слова

Выполняется только при включённом правиле.

1. **Безусловное удаление.** Если первое слово значения до удаления значащих слов
   есть в «Слова удаления кода.txt», код удаляется. От списка значащих слов не зависит.
2. **Связь с другим изделием** — для значений, начинающихся со значащего слова:
   - через предлог: `Уплотнения для заслонки DN50`;
   - через существительное в родительном падеже: `Крышка насоса AB12`,
     `Ремкомплект распределителя AB12`, `Комплект уплотнений клапана AB12`.

   Код в таком случае удаляется, в том числе для серий номенклатуры.
   Прилагательные, отглагольные существительные на `-ния`/`-тия` и слова
   из «Исключения родительного падежа.txt» пропускаются. Просмотр прекращается
   на коде, числе, союзе, аббревиатуре или после запятой. После слов-наборов
   (`комплект`, `набор`, `упаковка`, `пачка`, `партия`) следующее слово считается
   содержимым набора: `Комплект прокладок AB12` не удаляется.
3. **Классификатор остатка** (кроме серий номенклатуры): маркер каталога/модели
   или каталожный номер — на ручную проверку с результатом; только технические
   параметры или обозначение стандарта — код удаляется.

Удалённый правилом 12 код становится пустым: строка идёт в файл ручной проверки
с пустым исправленным кодом и в поиске дубликатов не участвует.

## Готовность кода для 1С

Код попадает в «Коды для загрузки в 1С.xlsx», если:

- состоит только из `0-9`, `A-Z` и доп. символов из настроек, без пробелов; или
- имеет форму «* *» — два блока из допустимых символов через один пробел,
  ни один из которых не является техническим обозначением (для серий
  номенклатуры технические блоки допустимы);
- правило 12 не отправило строку на ручную проверку;
- код не совпадает с кодом другого артикула (иначе — в файл дубликатов).

## Выходные файлы

Результаты сохраняются в `Результаты обработки\дд.ММ.гггг_ЧЧ.мм` рядом
с исполняемым файлом.

| Файл | Содержимое |
|---|---|
| `Коды для загрузки в 1С.xlsx` | готовые коды без дубликатов: артикул, код, группа выгрузки ИМ |
| `Коды для ручной проверки.xlsx` | исходный и исправленный код, критерий изменений, группа; лист «Легенда и сводка» |
| `Комм. код не был изменён.xlsx` | строки, не изменённые правилами |
| `Дубликаты в кодах для переноса в 1С.xlsx` | одинаковые коды у разных артикулов; создаётся, только если дубликаты найдены |
| `Применённые правила.txt` | сводка по правилам, категориям, сбоям и дубликатам |

При дубликатах на вкладке групповой обработки выводится предупреждение
со ссылкой на файл дубликатов. Сумма строк трёх основных файлов меньше общего
числа строк на количество дубликатов.

Выделение в файле ручной проверки:

| Выделение | Значение |
|---|---|
| красная заливка | пустой результат (кроме удаления по артикулу и правилом 12) |
| жёлтая заливка | необработанный остаток в конце значения |
| оранжевая заливка | подозрительный результат: стандарт, резьба, размерность, пробелы |
| синяя заливка | удалено значащее слово в начале значения |
| сиреневая заливка | сбой обработки строки, текст ошибки в «Критерий изменений» |
| красный шрифт в «Коммерческий код» | символы, затронутые правилами |
| красный полужирный артикул | код совпадает с кодом другого артикула в этом файле |

## Самопроверка

`Core/SelfTest.cs` — 75 кейсов в трёх наборах:

| Набор | Условия | Префиксы | Кейсов |
|---|---|---|---|
| Правила 1–11 | правило 12 выключено | `A`, `H`, `S`, `T`, `P`, `D`, `SRF…` | 53 |
| Правило 12 | правило 12 включено | `R`, `G` | 16 |
| Серии без удаления окончаний | серия `H74H`, доп. символ `-` | `K` | 6 (проверяется и готовность для 1С) |

Самопроверка использует рабочие файлы конфигурации. Ожидаемые значения
рассчитаны на стандартные списки: при изменённых списках слов, окончаний,
исключений или карты замен часть кейсов может давать иной результат.

## Известные ограничения

- Родительный падеж множественного числа без окончания (`прокладок`, `колец`)
  не распознаётся; совпадение форм им. и род. падежа может дать ложное
  срабатывание — такие слова добавляются в исключения.
- Форма «* *» допускает ровно два блока: `H74H-16P DN50 PN16` идёт на ручную проверку.
- Слова удаления кода сравниваются без словоформ: `Болты` не равно `болт`.
- Перезагрузка конфигурации во время групповой обработки не синхронизирована
  с ней; изменять настройки во время обработки не следует.

## Участие в разработке

1. Создайте ветку от `main`: `feat/...`, `fix/...`, `docs/...`.
2. Внесите правку и добавьте кейс в `Core/SelfTest.cs`.
3. Убедитесь, что все кейсы проходят.
4. Откройте pull request: что изменилось, какой кейс добавлен, на каких данных проверено.

Соглашения:

- file-scoped namespace, nullable-контекст;
- код в `Core` не зависит от `System.Windows.Forms`;
- комментарии по-русски, объясняют причину, а не действие:

  ```csharp
  // Диаметр начинается с 0 только как «0,» или «0.»: резьбы М00…/М004 не бывает,
  // поэтому «-М004-» в кодах вида КЭМ-М004-РФ01 резьбой не считается.
  ```
