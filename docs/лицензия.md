# Лицензия

Условия использования не определены — это внутренняя разработка.

Прежде чем делать репозиторий публичным, определитесь с лицензией:
отсутствие файла `LICENSE` означает, что по умолчанию все права
сохранены и никто не вправе использовать, изменять или распространять
код, даже если он лежит в открытом доступе.

## Варианты

**Публичный репозиторий, все права защищены.** Ничего не добавляйте.
Для GitHub это состояние по умолчанию, но оно неочевидно для читателей —
стоит явно написать об этом в README.

**Публичный репозиторий, свободное использование.** Выберите лицензию
осознанно:

| Лицензия | Разрешает | Требует |
|---|---|---|
| MIT | использование, изменение, распространение | сохранить уведомление об авторстве |
| Apache-2.0 | то же + явная патентная оговорка | сохранить уведомление, указать изменения |
| GPL-3.0 | то же, но производные тоже под GPL | раскрытие исходников производных |

Для внутреннего инструмента нормализации данных чаще всего достаточно
MIT или Apache-2.0. Если в проекте есть наработки, которые вы не хотите
отдавать наружу, репозиторий следует сделать приватным — лицензия
этого не заменяет.

## Что сделать

1. Определитесь, будет репозиторий публичным или приватным.
2. Для публичного — добавьте файл `LICENSE` с выбранным текстом
   и укажите лицензию в README.
3. Проверьте, нет ли в истории коммитов данных, которые нельзя
   публиковать: выгрузок номенклатуры, списков артикулов, путей
   с именами сотрудников.
